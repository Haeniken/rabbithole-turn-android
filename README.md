[English](README.en.md)

Android-клиент защищённых туннелей на базе WireGuard с транспортом через TURN/DTLS, подписками, управляемой маршрутизацией и автоматическими обновлениями через GitHub Releases.

Проект развивается как отдельное приложение с пакетом `com.rabbithole`.

## Возможности

- туннель WireGuard через несколько параллельных TURN/DTLS-потоков;
- адаптивный пул потоков: быстрый старт на полной мощности, снижение до четырёх
  потоков после длительного простоя и плавное восстановление под нагрузкой;
- выбор потока с учётом очереди, RTT, потерь и временного штрафа после ошибок;
- ограниченное восстановление порядка WireGuard-пакетов и стабильные полосы
  отправки без изменения формата самих пакетов;
- плавная смена Wi-Fi и мобильной сети по схеме make-before-break;
- режимы транспорта `proxy_v2`, `proxy_v1` и прямой TURN relay;
- TURN/UDP, включённый по умолчанию, с автоматическим возвратом к совместимому
  TURN/TCP;
- дополнительная защита полезной нагрузки WRAP;
- получение TURN credentials по ссылке на звонок;
- автоматическая обработка CAPTCHA с устойчивым браузерным профилем и переходом
  к ручной проверке через системное уведомление;
- подписки на конфигурации с обновлением каждые 12 часов и ручной кнопкой обновления;
- возможность отзыва подписки и ключа подключения на стороне сервиса;
- управляемая прямая маршрутизация российских сетей и доменов для профилей, которые явно требуют её;
- автоматическая загрузка и ежедневное обновление `geoip.dat` и `geosite.dat`;
- настраиваемые источники и категории GeoIP/GeoSite с безопасным ограничением размера таблицы маршрутов Android;
- запрет запуска профиля с прямой маршрутизацией, если необходимые геоданные отсутствуют или повреждены;
- глобальный список «Приложения вне туннеля» для приложений, которым всегда нужно обычное подключение;
- AdGuard DNS (`94.140.14.14`, `94.140.15.15`), включённый по умолчанию и
  управляемый отдельной галочкой в разделе «Маршрутизация»;
- раздача активного VPN через Wi-Fi, USB, Bluetooth и Ethernet: прозрачная
  маршрутизация на устройствах с root и локальный HTTP/SOCKS5-прокси без root;
- проверка задержки подключения;
- сгруппированные журналы приложения, туннеля, TURN/CAPTCHA, подписок и маршрутизации;
- включаемая детальная диагностика очередей, socket write, потерь, перестановки
  пакетов и выбранного TURN-транспорта;
- проверка новых версий при запуске и вручную в настройках;
- загрузка подписанного APK из GitHub Releases с проверкой SHA-256 и сертификата Android.

## Установка

Готовые стабильные сборки публикуются в разделе [Releases](https://github.com/Haeniken/rabbithole-turn-android/releases).
Постоянная прямая ссылка на актуальный APK: [rabbit-hole-latest.apk](https://github.com/Haeniken/rabbithole-turn-android/releases/latest/download/rabbit-hole-latest.apk).

Для обновлений Android должен разрешать приложению установку APK из этого источника. Все версии, начиная с первого публичного релиза, должны быть подписаны одним и тем же release-ключом. Если ранее была установлена локальная debug-сборка, перед первой установкой публичного релиза её потребуется удалить из-за другого сертификата.

## Добавление подключения

Кнопка `+` на главном экране поддерживает:

1. импорт подписки или конфигурации из буфера обмена;
2. добавление подписки по индивидуальной ссылке;
3. импорт конфигурации или архива;
4. сканирование QR-кода;
5. создание туннеля вручную.

Обычное нажатие по карточке выбирает подключение. Длительное нажатие открывает действия редактирования и удаления.

Описание TURN-метаданных и жизненного цикла соединения находится в [info/TURN_INTEGRATION_DETAILS.md](info/TURN_INTEGRATION_DETAILS.md). Обезличенный шаблон конфигурации — в [info/config_example.conf](info/config_example.conf).

## Геоданные маршрутизации

По умолчанию используются актуальные файлы проекта [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat):

- `geoip.dat` для российских сетей;
- `geosite.dat` для категории российских доменов.

Прямая маршрутизация применяется только к профилям, где это указано в полученной конфигурации. Для остальных профилей и обычного импорта поведение туннеля не меняется. Пути загрузки, категории и ручное обновление доступны в настройках. По умолчанию используются категории `RU` и `CATEGORY-RU`; несколько категорий можно указать через запятую.

Глобальный список «Приложения вне туннеля» хранится только на устройстве и применяется ко всем обычным и подписочным профилям при их следующем подключении. Выбранные приложения используют обычную сеть Android.

## Раздача VPN

Раздел «Раздача VPN» находится сразу под «Маршрутизацией». На устройстве с
root приложение использует закреплённый подмодуль VPNHotspot, отключает
аппаратный tethering-offload на время работы и прозрачно направляет downstream-
интерфейсы в активный VPN. При остановке правила и исходная настройка offload
восстанавливаются; собственные цепочки firewall пересоздаются идемпотентно.
IPv6 downstream блокируется, а для TCP применяется clamp MSS к MTU VPN-маршрута.

Без root приложение поднимает HTTP/SOCKS5-прокси только для адресов активной
точки доступа/модема. Системный прокси Windows 11 охватывает браузеры, но не
RDP и не приложения, которые игнорируют proxy-настройку. Для всего трафика в
интерфейсе приложения приведена готовая конфигурация официального sing-box с
TUN, `strict_route`, MTU 1280 и исключением адреса телефона из маршрута.
AdGuard DNS UDP/53 при этом проходит через SOCKS5 внутри VPN.

Подробности реализации, ограничения и порядок очистки описаны в
[info/VPN_SHARING.md](info/VPN_SHARING.md).

Геоданные, профили, подписки и настройки хранятся во внутреннем каталоге приложения и удаляются Android при удалении приложения.

## Сборка

Требуются JDK 17, Go 1.25, Android SDK 36, Android NDK 29, стабильный Rust с
targets `aarch64-linux-android` и `armv7-linux-androideabi`, а также
`cargo-ndk` 4.1.2.

```bash
git clone --recurse-submodules https://github.com/Haeniken/rabbithole-turn-android.git
cd rabbithole-turn-android
./gradlew :ui:assembleDebug
```

Локальная release-сборка без signing-переменных использует debug-ключ и предназначена только для разработки. Для production-подписи задаются:

```text
ANDROID_KEYSTORE_PATH
ANDROID_KEYSTORE_PASSWORD
ANDROID_KEY_ALIAS
ANDROID_KEY_PASSWORD
```

После этого:

```bash
./gradlew :ui:assembleRelease
```

## CI и релизы

- `Android CI` запускает unit-тесты, lint и debug-сборку.
- `Android Release` собирает APK Gradle, подписывает release-ключом из GitHub Secrets, проверяет подпись и публикует APK вместе с SHA-256 как Actions artifact.
- тег вида `v<version>` дополнительно создаёт GitHub Release. Версия тега должна совпадать с `wireguardVersionName` в `gradle.properties`.

Workflow использует следующие GitHub Secrets:

```text
ANDROID_SIGNING_KEYSTORE_BASE64
ANDROID_SIGNING_KEYSTORE_PASSWORD
ANDROID_SIGNING_KEY_ALIAS
ANDROID_SIGNING_KEY_PASSWORD
```

Закрытый ключ и пароли не должны храниться в Git.

## Этот проект построен на базе

- [kiper292/wireguard-turn-android](https://github.com/kiper292/wireguard-turn-android) — исходный форк с TURN-интеграцией, на базе которого продолжалась разработка клиента;
- [WireGuard for Android](https://git.zx2c4.com/wireguard-android) — исходный официальный Android-клиент и userspace backend;
- [vk-turn-proxy](https://github.com/cacggghp/vk-turn-proxy) — исходная идея TURN-транспорта;
- [lionheart](https://github.com/jaykaiperson/lionheart) — один из источников унаследованной transport-реализации; ссылка сохранена для атрибуции.
- [WINGSV](https://github.com/WINGS-N/WINGSV) и закреплённый подмодуль
  [VPNHotspot](https://github.com/WINGS-N/VPNHotspot) — root-daemon и схема
  прозрачной раздачи VPN.

Лицензии унаследованных компонентов сохраняются в [COPYING](COPYING), исходных файлах и подмодулях.
