# Раздача VPN

## Режимы

Страница `Настройки → Раздача VPN` управляет Wi-Fi, USB, Bluetooth и Ethernet
независимо. Флажок разрешает приложению обслуживать соответствующий downstream,
но наличие интерфейса проверяется отдельно: если Android ещё не включил точку
доступа или модем, приложение показывает ожидание и не открывает доступ из
других локальных сетей.

На Android 11 и новее root-режим может включать и выключать системный tethering
через отдельный `app_process`. На более старых версиях и без root пользователь
включает его на системной странице, ссылка на которую есть в том же меню.

## Root: прозрачная маршрутизация

В сборку входит закреплённый git-подмодуль `WINGS-N/VPNHotspot`, выбранный как
в WINGSV. Gradle собирает его Rust-daemon `vpnhotspotd` для `arm64-v8a` и
`armeabi-v7a`; Kotlin-контроллер использует routing/session API подмодуля.

При активном VPN приложение:

1. отключает Android tethering-offload и запоминает предыдущее значение;
2. создаёт routing-session для каждого разрешённого downstream-интерфейса;
3. разрешает forwarding только в текущий VPN-интерфейс;
4. блокирует downstream IPv6 и при включённом AdGuard передаёт daemon адреса
   `94.140.14.14,94.140.15.15`;
5. применяет `TCPMSS --clamp-mss-to-pmtu` в обоих направлениях.

Если VPN исчез, downstream-трафик отклоняется до появления нового VPN, поэтому
обычный uplink телефона не становится незаметным fallback. Перед каждым
применением собственные цепочки `RH_VPN_SHARE` и `RH_VPN_MSS` удаляются и
создаются заново. При штатной остановке routing-session откатывается,
daemon выполняет общий `Clean`, цепочки удаляются, а прежнее значение offload
восстанавливается. Предыдущее значение offload записывается до изменения в
приватный rollback-marker. После аварийного завершения следующий запуск по
этому marker выполняет ту же детерминированную очистку; оставшийся до запуска
reject является закрытым, а не открытым состоянием.

## Без root: HTTP/SOCKS5

Foreground service слушает на выбранном порту (по умолчанию `10808`), но
принимает только адреса, входящие в подсети реально активных downstream-
интерфейсов. При отсутствии VPN новые соединения отклоняются, а service
останавливается. Поддерживаются HTTP `CONNECT`, абсолютные HTTP-запросы,
SOCKS5 TCP `CONNECT` и UDP `ASSOCIATE`.

Системный прокси на подключённом устройстве не охватывает программы, которые
его игнорируют. В частности, RDP в Windows 11 не идёт через такой прокси.
Диалог «Настройка Windows 11» подставляет фактический адрес телефона и порт в
конфигурацию официального sing-box: TUN с MTU 1280 и `strict_route` отправляет
TCP/UDP в SOCKS5, а адрес телефона исключается из TUN, чтобы не образовать
петлю. AdGuard используется как обычный UDP DNS через тот же SOCKS5.

## Ограничения проверки

Unit-тесты проверяют границы IPv4/IPv6-подсетей, а сборка проверяет совместимость
Android API, Kotlin, Java и Rust/JNI. Реальную работу tethering, root, USB,
Bluetooth, Ethernet, vendor firewall/offload и Windows RDP необходимо проверять
на целевых устройствах: Android не предоставляет полноценной эмуляции этих
системных путей в JVM-тестах.
